# 3차 개선 기록

## 2026-05-28 Entity/API/Spring Security/AI 1차 정리

### 변경 범위

- Entity 관계 필드명을 실제 타입에 맞게 변경.
  - `userId` -> `user`
  - `categoryId` -> `category`
  - `reminderId` -> `reminders`
- Repository method와 service 로직을 변경된 관계 필드명 기준으로 정리.
- 기존 로컬 DB와의 호환을 위해 Task/Calendar join column 이름은 유지.
- Task API를 RESTful path 구조로 변경.
  - `POST /api/tasks`
  - `GET /api/tasks`
  - `PUT /api/tasks/{taskId}`
  - `PATCH /api/tasks/{taskId}/status`
  - `DELETE /api/tasks/{taskId}`
- Calendar API를 RESTful path 구조로 변경.
  - `POST /api/calendars`
  - `GET /api/calendars`
  - `PUT /api/calendars/{calendarId}`
  - `DELETE /api/calendars/{calendarId}`
- 프론트 Task/Calendar 호출 path를 새 API 계약에 맞게 변경.
- `spring-boot-starter-security`를 도입하고 session 기반 인증을 Spring Security `SecurityContext`와 연결.
- 인증이 필요한 API는 Spring Security에서 `401`로 차단하도록 변경.
- 테스트 범위를 확대.
  - Task owner 검증
  - Calendar owner 검증
  - Category owner 검증
  - BCrypt 비밀번호 저장/인증
  - 현재 사용자 식별 로직
  - AI 응답 parsing
  - Task controller session 인증
- 프론트 build warning을 정리.
  - unused state/import 제거
  - 알림 select가 `repeat` 상태를 잘못 쓰던 부분을 `reminder` 상태로 연결
- AI 기능 1차 책임 분리.
  - `OpenAiClient`: OpenAI HTTP 호출과 요청 생성 담당
  - `AiResponseParser`: OpenAI 응답에서 schedule item parsing 담당
  - `AiCommandService`: AI 응답 item의 type별 command dispatch 담당
  - `ScheduleCommandService`: Task/Calendar/Reminder 생성과 reminder 선택 목록 담당
  - `OpenAIService`: OpenAI 호출 orchestration과 log 저장 흐름 담당
- API contract 문서 추가.
  - `docs/계약/API_계약.md`
- Flyway DB migration 도입.
  - `V1__init_schema.sql` 추가
  - local profile `ddl-auto=validate` 전환
  - 기존 DB는 baseline으로 추적 시작

### 검증 결과

- `bash ./mvnw test`: 성공, 테스트 14건 통과.
- `npm run build`: 성공, ESLint warning 0개.
- backend `local` profile 기동: 성공.
- 기존 `timetodo` DB에서 Flyway baseline 및 Hibernate validate 성공.
- 빈 임시 DB `timetodo_flyway_check`에서 Flyway `V1` 적용 및 Hibernate validate 성공.
- 세션 없이 `GET /api/tasks`: `401`.
- 로그인 후 `GET /api/user/me`: `200`.
- 로그인 후 `GET /api/tasks`: `200`.
- 로그인 후 task 생성/수정/status 변경: `200`.

### 남은 리스크

- Spring Security는 session 인증까지만 적용했다. 운영 배포 전에는 CSRF, cookie `SameSite`, `Secure`, CORS origin 정책을 다시 점검해야 한다.
- AI가 생성하는 Task/Calendar는 아직 기본 category ID `1`을 사용한다.
- 기존 DB는 Flyway `V1`을 실제 적용하지 않고 baseline 처리했다. 새 DB에서는 `V1`이 적용된다.
