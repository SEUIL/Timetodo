# 4차 개선 기록

## 2026-05-28 2차 개선: API/Validation/DB/UX 정리

### 변경 범위

- AI 생성 Task/Calendar의 기본 category ID `1` 하드코딩 제거.
  - 사용자별 `AI 기본-{userId}` category를 조회하거나 없으면 생성.
  - AI 생성 흐름이 특정 DB row ID에 의존하지 않도록 변경.
- Category API를 RESTful path로 정리.
  - `POST /api/categories`
  - `GET /api/categories`
  - `PUT /api/categories/{categoryId}`
  - `DELETE /api/categories/{categoryId}`
  - 기존 legacy path는 호환용으로 유지.
- Calendar search API를 query parameter 기반으로 정리.
  - 기존 `GET` + 여러 `@RequestBody` 구조 제거.
- DTO validation 추가.
  - Task 필수값 검증.
  - Calendar 필수값과 시간 범위 검증.
  - Category 색상 형식 검증.
  - User 비밀번호 최소 길이 검증.
- `GlobalExceptionHandler` 추가.
  - validation 실패 응답 형식 통일.
  - `ResponseStatusException` 응답 형식 통일.
- DB migration 후속 정리.
  - Task/Calendar join column을 `category_id`, `user_id`로 정리.
  - `V2__rename_relation_columns.sql` 추가.
- JSON 라이브러리 중복 warning 제거.
  - `org.json` 의존성 제거.
  - `OpenAiClient`를 Jackson 기반으로 변경.
- Controller 테스트 확대.
  - Category 인증, validation, 삭제 응답 검증 추가.
  - Task/Calendar 인증, 생성 validation, 세션 사용자 service 호출, 권한 실패 응답 검증 추가.
- AI command/domain 생성 테스트 추가.
  - `ScheduleCommandServiceTest` 추가.
- 프론트 UX 일부 정리.
  - 로그인 실패를 alert 대신 화면 내 오류 메시지로 표시.
  - 일정 추가 시 제목 누락/시간 범위 오류를 저장 전에 차단.
- 배포 profile 기본값 추가.
  - `application-prod.properties`
- E2E 수동/자동화 후보 시나리오 문서 추가.

### 검증 결과

- `bash ./mvnw test`: 성공, 테스트 30건 통과.
- `npm run build`: 성공.
- 기존 `timetodo` DB에서 Flyway V2 migration 적용 및 Hibernate validate 성공.
- 빈 임시 DB에서 Flyway V1+V2 migration 적용 및 Hibernate validate 성공.
- 임시 DB `timetodo_flyway_check` 삭제 완료.

### 남은 리스크

- Controller 통합 테스트는 update/delete 정상 흐름과 검색 API까지 모두 커버하지는 않는다.
- E2E는 문서화 단계이며 Playwright 같은 자동화 도구는 아직 도입하지 않았다.
- 배포 profile은 기본 설정만 추가했으며 실제 배포 환경 검증은 하지 않았다.
- README 시각 자료 보강은 사용자가 실제 화면 screenshot을 준비한 뒤 진행하는 것이 적절하다.
