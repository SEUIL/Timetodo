# 2차 개선 기록

## 2026-05-28 인증/권한/API 구조 개선

### 변경 범위
- 서버 API가 `userId` 쿠키 값을 신뢰하지 않도록 변경.
- 로그인 성공 시 서버 세션에 `userId`를 저장하고, 보호 API는 세션 기준으로 현재 사용자를 확인.
- `/api/user/me`를 추가해 프론트가 새로고침 후에도 로그인 상태를 확인할 수 있게 변경.
- Task, Calendar, Category, Reminder, Log의 수정/삭제/조회/생성 흐름에 owner 검증 추가.
- Task, Calendar, Reminder, Log의 Entity 직접 반환을 DTO 반환으로 정리.
- 프론트 API 호출을 `frontEnd/src/api/client.js`의 공통 axios client로 통합.
- `localhost:8085` 하드코딩, `fetch`/`axios` 혼재를 제거.
- 존재하지 않던 `/api/schedule/*` 호출을 기존 `/api/chat/add`, `/api/calendar/find` 흐름으로 교체.
- Spring 설정을 공통 `application.properties`와 로컬 전용 `application-local.properties`로 분리.
- owner 검증 단위 테스트를 추가.

### 검증 결과
- `bash ./mvnw test`: 성공, `TaskServiceTest` 2건 통과.
- `npm run build`: 성공, 기존 unused 변수 중심 ESLint warning 존재.
- backend `local` profile 기동: 성공.
- 세션 없이 `GET /api/user/me`: `401`.
- 세션 없이 `GET /api/task/find`: `401`.
- 로그인 후 `GET /api/user/me`: `200`.
- 로그인 후 카테고리 생성: `200`.
- 로그인 후 할 일 생성: `200`.
- 다른 사용자 세션으로 같은 할 일 수정: `403`.
- 다른 사용자 세션으로 같은 할 일 삭제: `403`.
- 소유자 본인 세션으로 할 일 수정: `200`.

### 남은 리스크
- Spring Security 정식 도입은 아직 하지 않았고, 현재는 HttpSession 기반 최소 인증 구조다.
- Calendar/Task API의 요청 형식은 기존 프론트 호환을 위해 유지했다. RESTful path 구조 정리는 별도 단계로 남아 있다.
- Entity 필드명 자체는 아직 `userId`, `categoryId`처럼 남아 있다. 실제 타입은 Entity이므로 장기 리팩터링에서 `user`, `category`로 변경 필요.
- 프론트 unused 변수 warning은 build를 막지는 않지만 추후 정리 대상이다.
