# E2E 시나리오

## 목적

브라우저 기준으로 핵심 사용자 흐름이 실제로 이어지는지 검증한다.

## 우선 수동 검증 시나리오

| 순서 | 화면 | 동작 | 기대 결과 |
|---|---|---|---|
| 1 | 로그인 | 잘못된 계정으로 로그인 | 화면 안에 오류 메시지 표시 |
| 2 | 로그인 | 정상 계정으로 로그인 | `/home` 이동 |
| 3 | 사이드바 | 카테고리 생성 | 새 카테고리가 선택 가능 |
| 4 | 할 일 | 제목, 마감일, 카테고리 입력 후 저장 | 할 일 목록에 추가 |
| 5 | 할 일 | 상태 변경 | 새로고침 후에도 상태 유지 |
| 6 | 캘린더 | 제목, 시작/종료 시간, 카테고리 입력 후 저장 | 캘린더에 일정 표시 |
| 7 | 캘린더 | 종료 시간이 시작 시간보다 빠른 일정 저장 시도 | 저장 차단 |
| 8 | 로그아웃 | 로그아웃 후 보호 API 접근 | 로그인 필요 상태 |

## 자동화 후보

Playwright 도입 시 우선 자동화할 흐름:

1. 로그인 실패 메시지 확인
2. 로그인 성공 후 홈 진입
3. 카테고리 생성
4. 할 일 생성 및 상태 변경
5. 일정 생성
6. 로그아웃 후 보호 화면 접근 차단

## 전제

- backend: `http://localhost:8085`
- frontend: `http://localhost:3000`
- test DB는 매 테스트 실행 전 초기화하거나 전용 계정을 사용한다.
- 비밀번호, API key 등 secret은 테스트 로그에 남기지 않는다.
