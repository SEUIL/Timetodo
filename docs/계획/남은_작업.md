## P1. 인증 구조 고도화

현재는 Spring Security session 기반 인증 구조다.

완료된 것:

- 서버가 `userId` 쿠키를 신뢰하지 않도록 변경.
- 로그인 성공 시 세션에 사용자 ID 저장.
- `/api/user/me` 추가.
- 보호 API에서 현재 사용자 확인.
- `SessionAuthenticationFilter`로 session 사용자 정보를 Spring Security `SecurityContext`에 연결.
- 미인증 API 요청은 Spring Security entry point에서 `401`로 차단.

남은 선택지:

1. 세션 cookie 정책, CSRF 정책, 운영 배포 시 SameSite/Secure 설정을 보강한다.
2. JWT 기반 전환은 모바일/외부 API 요구가 생긴 뒤 재검토한다.

권장:

- 현재 포트폴리오와 로컬 개발 범위에서는 Spring Security session 구조를 유지한다.
- JWT는 배포/모바일/외부 API 요구가 생긴 뒤 결정해도 된다.
